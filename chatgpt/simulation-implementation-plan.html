01 / AGREED BEHAVIORThe model we are implementing

Liquid assets

The input series is a total-return index scaled to the desired starting dollar value. Its first value initializes liquid assets. Later value ratios supply returns; simulated balances then reflect private cash flows.

Fund universe

Every FundVintage is a specific investable fund with its own dated unit cash flows and NAVs. Commitment date and closing date mean the same thing. There are no previously committed funds at inception.

Commitment policy

Annual percentages are supplied by fund type, represented by strategy. A year without a closing carries its percentage forward for that type. The next closing-year pool combines missed percentages with that year’s target and is split using supplied fund weights. Dollars are calculated at each fund’s closing NAV.

Timing and liquidity

Off-grid closings move to the next observation. Private NAV adjusts for cash flows between marks. If aggregate calls exceed available cash at an observation, simulation stops and returns a shortfall report.

No separate initial liquid value. If the first index value is 100, the engine starts with $100. An index rebased to 100 therefore simulates $100 unless scaled before input. Future index levels are a return source, not replacement portfolio balances.

Scope: implement the Simulation class and supporting config/result objects. Do not generate additional funds, shift existing fund histories, add inflation or external wealth flows, or add stochastic behavior. Those features are outside the requested replication.

State ownership: snapshot the relevant input data during construction. Keep calculated dollar commitments in private simulation state; do not change the supplied objects’ commitment_size or history lists. Each run() starts from fresh state and produces identical results for identical inputs.

Because all commitments are calculated by this engine, read the normalized histories and multiply by the engine’s stored commitment. Existing commitment_size fields are not used for sizing; report any nonzero supplied values as ignored input metadata.

No additional carryforward input is required. Derive missed percentages from the annual policy and supplied closing schedule. Start with zero carried percentage at simulation inception. Policy years before the first model date’s year are excluded and flagged; importing an opening backlog would be a separate extension.

03 / DATES AND EVENT RULESOne output grid, explicit event boundaries

  1. Output dates: exactly the dates in the liquid series. Do not resample it to a monthly or annual grid.
  2. Closing assignment: effective closing is the first model date greater than or equal to the actual closing date. Use a vectorized left-sided date search.
  3. Annual policy lookup: use the actual closing date’s calendar year for the pooled rate and weight group. A December closing mapped to a January observation still uses December’s pool; it must not absorb January’s new target.
  4. Period boundaries: after the first date, cash-flow buckets are (previous_date, current_date]. Include every individual flow in the interval exactly once, even if no event is dated exactly on an observation.
  5. First date: opening liquid assets equal the first index value; the return factor is 1. Process closings, flows and NAV marks dated on that first date. No earlier fund exposure or cash flow is allowed.
  6. Same observation: all funds closing at that observation are sized from the same pre-call liquid balance. Never update the sizing balance fund by fund.
  7. Horizon: funds closing after the final observation are not activated. Record them as outside the horizon. Do not redistribute their weights to earlier funds. Truncate later flows and marks, without forcing remaining private NAV to zero.

Period-level convention. All cash transfers are applied after the interval’s liquid return. This preserves the source’s ordering, but does not model cash earning returns after an intra-period distribution or losing returns after an intra-period call. A shortfall is assessed at observation dates; intra-period liquidity deficits are not detected. Grid frequency can therefore affect results.

Weights define shares of the closing year’s pooled percentage, including carryforward, not a fixed annual dollar pool. Funds closing at different observations use different liquid balances, so their eventual dollar commitments need not be proportional to their weights.

For a horizon covering only part of a year, provide the complete intended same-year fund group to validate the weights. Funds outside the horizon retain their assigned shares; no automatic renormalization takes place.

Percentage carryforward by fund type

Maintain a separate percentage budget for every type, including types with no available fund anywhere in the supplied horizon. Add each calendar year’s target once, not once per observation. The inception year receives its full supplied target with no automatic prorating. Process all intervening calendar years even when the observation grid skips a year.

pool[year, type] = carried_percentage_from_prior_years + annual_rate[year, type]
  1. No funds close in that actual calendar year: retain the whole pool as unallocated carryforward. No dollar commitment, cash reservation, or private NAV is created.
  2. One or more funds close: allocate that pool once to the year’s complete fund group using the supplied weights. Each fund receives a fixed percentage entitlement: effective_rate[fund] = pool[year, type] × weight[fund].
  3. Reserve unclosed shares: after allocation, the pool is no longer unallocated carryforward. Shares belonging to later funds remain reserved percentage entitlements until their effective closing. Do not give the whole pool to the first fund or reuse it in subsequent years.
  4. Convert at closing: multiply each entitlement by that fund’s closing-date sizing liquid NAV. After the observation succeeds, mark that entitlement as used. If the NAV is zero, the resulting dollar commitment is zero and the applied percentage is still used; there is no automatic retry.
  5. End of horizon: report both unallocated carryforward and reserved shares for funds not yet activated. Do not force investment, redistribute weights, or drop the outstanding percentages.

The annual allocation can be prepared from the known schedule before the cash simulation. Reporting must nevertheless accrue targets only when their calendar year is reached. A future scheduled allocation is not a completed investment. Budgets are independent across types and percentages add arithmetically without compounding, inflation, or conversion to historical dollar amounts.

# Prepare percentage entitlements, independently for each fund type.
carry = 0.0
for year in all_calendar_years_from_inception_through_horizon:
    pool = carry + annual_rate[year, fund_type]
    cohort = funds_with_actual_closing_year_and_type(year, fund_type)
    if not cohort:
        carry = pool
    else:
        for fund in cohort:
            effective_rate[fund] = pool * weight[fund]
            # Retain source-year contributions for the audit trail.
        carry = 0.0  # Transferred to reserved shares, not yet used.

04 / SIMULATION ALGORITHMPreserve the source’s cash ordering

For observation k, let L_open be the last completed closing liquid balance, and let I[k] be the supplied total-return index. Initially L_open = I[0] and all private NAV and commitments are zero.

1

Read opening balances and advance the budget ledger

Snapshot liquid assets and each active fund’s prior closing NAV. Calculate opening private NAV by fund type and opening total value. Opening exposures exclude funds that will activate at this observation. In candidate state, accrue any calendar-year targets crossed since the previous observation, exactly once, and update carryforward/reserved shares from the prepared annual allocation.

total_open = L_open + sum(private_nav_open)
2

Apply the liquid return

Use the actual ratio of observations. At the first date, use a factor of 1.

factor = 1 if k == 0 else I[k] / I[k - 1]
liquid_after_return = L_open × factor
3

Receive distributions from previously active funds

For each fund already committed before this observation, sum its positive unit flow entries in the interval and scale by its fixed dollar commitment.

sizing_liquid_nav = liquid_after_return + distributions_existing
4

Set commitments for the closing cohort

For every fund mapped to this date, look up its prepared percentage entitlement, based on the pooled percentage for its actual closing year and its supplied weight. Calculate all commitments against the same sizing_liquid_nav, then keep them fixed for the fund’s entire simulated life.

effective_rate[f] = pooled_rate[actual_closing_year, strategy] × weight[f]
commitment[f] = effective_rate[f] × sizing_liquid_nav

A commitment alone does not reduce cash or create NAV. Zero current-year rates do not cancel accumulated percentages: a fund can still receive a commitment from carryforward. Zero effective-rate or zero-weight funds may be activated with a zero commitment for a complete audit trail.

5

Scale this period’s remaining flows

Include calls from existing and newly activated funds. Also include distributions from newly activated funds after commitment sizing. This avoids circular sizing if a fund closes and distributes within the same bucket.

Separate positive and negative entries before aggregation. Do not recover gross distributions or calls from an already-netted interval total.

calls = Σ commitment[f] × Σ max(-unit_flow, 0)
distributions_new = Σ commitment[new_fund] × Σ max(unit_flow, 0)
6

Check liquidity before completing the period

cash_available_for_calls = sizing_liquid_nav + distributions_new
liquid_close_candidate = cash_available_for_calls - calls

If the candidate is below negative cash tolerance, stop with a structured shortfall result. Do not cap calls, borrow, resize commitments, or continue subsequent periods. Aggregate calls first so the result is independent of fund ordering.

7

Roll private NAV and save the completed observation

Advance the fund event histories using the NAV rules below. Save closing liquid assets, private NAV, flows, commitment events, and total value. Move successfully activated funds’ percentage entitlements from reserved to used. Commit the financial state and percentage ledger atomically only after the period passes its checks.

total_close = liquid_close + sum(private_nav_close)

05 / PRIVATE NAVProcess all marks, including off-grid marks

Build a normalized NAV path from each fund’s raw dated events, starting at zero. Merge flows and NAV marks into chronological order. Between explicit marks, adjust NAV for cash flows:

unit_nav_after_flow = unit_nav_before_flow - signed_unit_flow

A negative flow is a capital call and increases NAV; a positive flow is a distribution and decreases NAV. An explicit mark replaces the running estimate. At each model date, use the final normalized NAV after all events on or before that date, then scale it by the fund’s calculated commitment.

  • Same-day convention: apply the day's aggregate net flow, then the NAV mark. Marks are assumed to include that day’s cash flows. Check inferred NAV after all same-day events, so intermediate entry order does not create a false negative-NAV error.
  • Off-grid mark: retain its actual date within the event sequence. A March 20 mark must affect a March 31 observation even without an exact March 31 mark.
  • Missing mark: continue cash-flow adjustment; do not invent investment returns or use a future mark.
  • Explicit zero: a zero mark resets NAV to zero. It is not missing data.
  • Duplicate marks: reject multiple NAV marks on the same fund/date.
  • Negative inferred NAV: report a valuation-data error rather than silently clamp a material negative value. If it occurs between marks, request adequate valuation data or a separately agreed alternative policy.

Example: a $20 call, followed by a $23 NAV mark, followed by a $3 distribution produces a closing NAV of $20. Applying every cash flow after the latest mark would double-count the earlier call; chronological processing avoids this.

Do not use monthly_nav(): its month-specific branches and exact-date matching are unsuitable here. Also avoid latest_nav, total_called, and total_distributed inside the engine because those properties include the entire supplied history. monthly_flows() has useful interval semantics, but its net totals cannot replace gross-flow aggregation.

Shortfall behavior: return all successfully completed observations and a separate failure record for the first failed observation. Include the date and interval, opening liquid balance, return factor, existing/new distributions, available cash, calls required, deficit, candidate commitments, and per-fund calls. The failed date is not presented as a completed portfolio row; attempted commitments are clearly labeled and are not committed to completed state.

If the very first date fails, completed tables are empty but the failure record is populated. Structural input errors raise a descriptive validation exception before running. A valuation-data failure uses a separate descriptive exception with fund/date context; it must not be mislabeled as a liquidity failure.

On a shortfall, do not mark attempted percentage entitlements as used. Return the last completed budget ledger plus a clearly labeled candidate budget snapshot for the failed date, including target accruals and attempted entitlement use. No later fund may consume those shares because the simulation stops.

Reconciliation identities

liquid_close = liquid_open + liquid_investment_pnl
               + distributions - calls

private_valuation_pnl = private_nav_close - private_nav_open
                        - calls + distributions

total_close = liquid_close + private_nav_close
total_close - total_open = liquid_investment_pnl
                           + private_valuation_pnl

Commitments are obligations, not immediate asset transfers. They must never appear directly as a deduction in the liquid or total-value identities.

For each fund type at each completed observation:
cumulative_target_percentage = cumulative_used_percentage
+ unallocated_carried_percentage
+ reserved_percentage

This identity reconciles percentage policy. It does not assert a historical dollar target: each used percentage is valued at its receiving fund’s closing NAV. There is no meaningful dollar total for outstanding percentages until a future closing NAV is known.

07 / VALIDATIONFail clearly on ambiguous inputs

  • Validate positive finite index levels, unique increasing dates, and nonempty input. Limit this version to calendar dates because the attached fund model stores date; reject intraday observations and timezone ambiguity.
  • Require a unique fund name, a canonical fund-type string, and a commitment date for every fund. Do not infer closing from vintage_year or the first flow.
  • Reject closing dates before inception and nonzero NAVs or any nonzero flows before a fund’s actual closing date. Pre-closing zero marks may be ignored.
  • Require finite nonnegative rates and weights. Do not impose an arbitrary 100% cap on summed commitment rates: commitments need not be called immediately.
  • Validate weights over the full supplied closing-year/type group. Require explicit rates for every calendar year from inception through the horizon and every configured type, including years/types without closings; reject missing cells rather than interpret them as zero. The configured types are the union of policy columns and supplied fund types. Policy-only types are valid and accumulate carryforward.
  • Do not cap accumulated percentages at 100%, normalize them across types, or expire them. No-closing years add to carryforward. Rates outside the modeled calendar years are excluded and flagged, not silently imported into an opening backlog.
  • Validate finite flow values, correct entry types, nonnegative explicit NAV marks, and one NAV mark per fund/date. Preserve separate same-date call/distribution entries.
  • Assume a common currency across liquid values and all dollar commitments. No FX conversion is included.
  • Document that already-netted source entries cannot be decomposed into gross calls and distributions. Accurate gross reporting requires those events to be supplied separately.

Attachment compatibility: FundVintage.__post_init__() currently restricts vintage_year to the current year plus one. Long future simulations will require relaxing that validation in the class or its data adapter. Its cleaner also silently removes some invalid entries; the engine cannot detect data already discarded before it receives the objects.

08 / WORKED EXAMPLETwo closings, one annual percentage

Use liquid index values of $1,000,000 on January 1, $1,100,000 on March 31, and $1,210,000 on June 30. BUYOUT has a 10% annual commitment rate. Fund A closes February 15 with weight 60%; Fund B closes May 10 with weight 40%.

March 31 flowsA calls 25% of commitment within the interval; no distributions or NAV marks.Call $16,500; liquid $1,083,500; private NAV $16,500; total $1,100,000.
June 30Grow the simulated liquid balance 10% to $1,191,850. A distributes $3,300. B sizing base is $1,195,150.B commitment = $1,195,150 × 10% × 40% = $47,806.
June 30 flowsB calls 25%, or $11,951.50. A has no further calls; no NAV marks arrive.Liquid $1,183,198.50; A NAV $13,200; B NAV $11,951.50; total $1,208,350.

The second-period return uses the ratio 1,210,000 / 1,100,000, but is applied to $1,083,500. It does not overwrite cash with $1,210,000. Total commitments are $113,806; the 60/40 weights do not create a 60/40 dollar split because closing NAVs differ.

Failure variant: if aggregate June calls instead equal $1,200,000 with no additional distributions, available cash is $1,195,150. Stop on June 30 with a $4,850 shortfall and return January/March as the completed observations.

09 / BUILD SEQUENCEImplement in six bounded stages

  1. Define contracts. Create the config, result, diagnostic, and shortfall data classes, including the percentage-budget ledger. Document the first-date, year-selection, carryforward, same-day-mark, and new-fund-distribution conventions alongside them.
  2. Normalize and validate. Snapshot input objects, enforce unique IDs and strategy keys, verify dates/rates/weights, and flag out-of-horizon data. Address the fund class’s future-year restriction where needed.
  3. Prepare events and percentage entitlements. Walk every calendar year for each type, pool missing-year rates and reserve weighted shares for the next closing-year group. Preserve source-year attribution. Map closings and individual flows to model observations. Precompute unit gross calls/distributions and normalized NAV at each model date using chronological marks and flows. Do not repeatedly rescan entire histories.
  4. Implement the state loop. Track active funds, fixed commitment amounts, liquid balance, prior private NAV and the percentage ledger. Accrue annual targets once, then apply returns → existing distributions → new commitments → remaining flows → liquidity check → closing NAV/results. Finalize used entitlements only on successful observations.
  5. Build reporting. Produce portfolio, fund and strategy tables; the percentage-budget ledger; commitment audit entries; structured shortfall output; and both monetary and percentage reconciliation diagnostics. Support simulate() as a thin alias for run().
  6. Verify and document. Run the acceptance cases below and a small manual reconciliation fixture. Document the intentional differences from the old source and the interval-level liquidity limitation.

Suggested module separation: simulation.py for the public class/config/results, simulation_events.py for event alignment and unit NAV reconstruction, and tests/test_simulation.py for behavior and accounting tests. Keep helper methods private unless another consumer actually needs them.

Use NumPy/Pandas for arrays and reports. Event preparation can use sorted sweeps and date searches; the main loop operates on prepared fund-by-date arrays. Avoid constructing zero-commitment placeholder fund objects or quadratic repeated calls to history-scanning methods.

11 / SOURCE COMPATIBILITYPreserved logic and deliberate changes

Preserved: liquid returns precede private flows; distributions from active funds feed the commitment-sizing balance; all commitments in a period use the same pre-call base; capital calls include newly activated funds; commitment creation itself does not spend cash.

Replaced as requested: annual array positions become calendar-date observations; synthetic annual vintages become the supplied specific funds; fund-type rates and weights determine commitments; missing-year percentages accumulate independently by type and join the next closing-year pool. There is no separate starting-liquid parameter, historical fund cohort, or total-market-value commitment option.

Corrected explicitly: no hard-coded flow length, overwritten exposure bucket, silent negative liquidity, or month-specific NAV handling. The first observation has no preceding return interval but still processes same-date events. Newly closing funds’ same-period distributions are retained after sizing; the original source would lose those distributions.

Implementation defaults requiring no further configuration: actual closing year selects the percentage pool; carryforward starts at zero and annual targets are not prorated; pooled percentages use the supplied same-year weights; same-day NAV marks are post-flow marks; funds remain distinct by unique name; currency is common; no exogenous wealth flows or inflation are applied. These rules belong in the public API documentation and tests.
